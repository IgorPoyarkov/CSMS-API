# Агент разметки правил НПА по ОКПД2 (471-р, 1875, 2604)

Короткий бриф для следующего агента: что уже построено, как запускать и где
ограничения. Подробности по справочнику ОКПД2 — `docs/tasks/reference-data.md`.
Про второй агент (LLM-разбор неявных совпадений и спорных позиций) —
`docs/tasks/npa-llm-agent.md`; он реализован на локальной модели Ollama,
предложения попадают только в `needs_review`.

## Цель и границы

По официальным актам проставить правила по кодам ОКПД2 в таблице из 21 066
записей, включая коды, которые в акте названы наименованием, а не кодом.
Спорные правила не угадываются: они получают `needs_review` и идут человеку.
Источник текста — только `http://publication.pravo.gov.ru` (или загруженная
заказчиком копия `.pdf`/`.docx`). Придумывать коды и форматы запрещено.

## Устройство

- `src/Csms.Infrastructure/Npa/` — пайплайн:
  - `PravoDocumentClient` — поиск акта по номеру с портала публикования,
    выбор более поздней публикации; `PageSize=30` (50 даёт HTTP 400).
    Портал отдаёт оригинал и поправки отдельно, consolidated-редакции нет.
  - `NpaDocumentParser` — PDF и DOCX → строки таблицы. PDF — сканы без
    текстового слоя: рендер через `Docnet.Core` (`PageDimensions(dpi/72.0)`,
    иначе страницы 471-р уходят в 59 500 × 84 200 px), OCR Tesseract с русским
    языком в двух проекциях (полная страница psm 6 для текста и цифровая с
    whitelist `0123456789.` для кодов), совпадение по Y. BMP пишется вручную.
  - `NpaLayoutParser` — само настраиваемая граница колонки кодов (медиана левых
    координат + допуск), сборка `NpaTableRow`, `NpaExclusion`, `NpaUnresolvedRow`.
  - `Okpd2CodeResolver` / `Okpd2Catalog` — главный фильтр: число считается кодом
    только если оно есть в активном справочнике `nsiOKPD2`. Восстановление
    `262011110` → `26.20.11.110` — только при однозначном совпадении. Коды
    других классификаторов отбрасываются.
  - `NpaRuleClassifier` — `include` / `exclude` / `conditional`. Оговорка
    «кроме мебели» внутри наименования позиции — уточнение включения, а не
    исключение всей строки; явные «кроме», «за исключением», «не применяется»
    дают `exclude`; условия дают `conditional` + `needs_review`.
  - `NpaRuleBuilder` — явные коды и оговорки дают точные правила: «кроме кодов …»
    внутри строки, перенос оговорки на следующую строку OCR и обрывки оговорки
    в `unresolvedJson` (оговорка про коды или минимум два кода с точками).
    «Кроме танкеров» в наименовании остаётся уточнением `include`, а не
    исключением. Одиночный явный код из неразобранной строки даёт `include` +
    `needs_review` (разложка не подтвердила колонку). Даты и номера пунктов
    в правила не попадают. Позиции без кода подбираются по наименованию из
    справочника и всегда помечаются `needs_review`.
  - `NpaRuleHierarchy` — наследование по дереву ОКПД2: самый длинный префикс,
    исключение сильнее включения предка; унаследованные правила материализуются
    в `ref.npa_rules` с `IsInherited=true` и `InheritedFrom`.
  - `NpaSyncService` — скачивание, вычисление SHA-256, сравнение версий, сборка
    правил, атомарная публикация и история версий. `force=true` создаёт новую
    версию с суффиксом `-r2`, `-r3` … через `INpaRuleStore.VersionExistsAsync`.
  - `NpaSyncWorker` — фоновая проверка новых публикаций (`Npa:Enabled`).
- `ref.npa_documents` / `ref.npa_rules` — миграции `20261119203230_AddNpaRules`
  и `20261119225748_AddNpaCheckTimestamps`, индекс
  `("Okpd2Code" text_pattern_ops)` для префиксного поиска.
- У документа разделены `FetchedAt` (когда опубликована эта версия правил) и
  `LastCheckedAt`/`LastCheckStatus`/`LastCheckMessage` (когда официальный текст
  последний раз проверялся, даже если версия не изменилась).
- Хранилища: `EfCoreNpaRuleStore` (PostgreSQL) и `InMemoryNpaRuleStore`
  (`EIS_STORE=memory`). Публикация версии — в транзакции, активная ровно одна.

## Расписание проверки

- `Npa:CheckTime = "03:00"` — ежедневный старт по московскому времени (UTC+3,
  сезонного сдвига нет). Задержка считается от текущего времени сервера, а не от
  момента запуска процесса.
- `Npa:CheckDelayMinutes = 30` — пауза после завершения каждого акта перед
  следующим. Акты обрабатываются строго последовательно (`NpaSyncWorker`), чтобы
  OCR и запросы к порталу публикования не конкурировали.
- Проверка фиксируется в БД даже при `up_to_date` и при ошибке: в реестре видно
  и время последней проверки, и время публикации активной версии.

## API

- `GET /api/npa/config` — список ведомых актов и режимов (`checkTime`,
  `checkDelayMinutes`, `timeZone`).
- `GET /api/npa/documents`, `GET /api/npa/documents/{code}` — версии и активная
  версия. Поля `fetchedAt` (обновление версии), `lastCheckedAt`,
  `lastCheckStatus`, `lastCheckMessage` (последняя проверка) и `unresolvedJson`
  (строки для ручной разметки).
- `GET /api/npa/documents/{code}/rules?search=&status=&skip=&take=&directOnly=true`
  — правила активной версии (постранично; `skip` обязателен для выгрузки всех
  17 тыс.). `directOnly=true` отдаёт только прямые правила (107/973/58) — этого
  достаточно фронту, чтобы восстановить дерево по префиксам ОКПД2.
- `GET /api/npa/documents/{code}/effective?okpd2Code=...&includePending=false`
  — действующее правило для кода (ближайший предок).
- `POST /api/npa/documents/{code}/sync?force=true&dryRun=false` — скачать и
  разобрать официальный текст; новая версия публикуется атомарно.
- `POST /api/npa/documents/{code}/upload` — разметить свою редакцию
  (`.pdf`/`.docx`, `multipart/form-data`, поле `file`, до 32 МБ).
- `POST /api/npa/documents/{code}/rules/{okpd2Code}/verify` — решение человека:
  `approved` / `rejected` / `needs_review` с заметкой.

## Потребитель на фронте (`csms`)

- `GET /api/references/nsiOKPD2/all` — весь активный снимок без `payloadJson`
  (21 066 кодов); `GET /api/references/{dataset}/items` остаётся для поиска.
- `src/services/Npa/npa.api.ts` — typed-клиент: `fetchNpaDirectRules`,
  `useNpaDocuments`, `useNpaRuleIndex`, `useNpaEffective`.
- `src/services/Npa/npaControl.ts` — синхронный резолвер по прямым правилам
  (самый длинный префикс, `exclude` сильнее) для zod-схем и `useMemo`.
- `useOkpd2Dictionary` строит справочник по снимку НСИ, накладывает локальные
  признаки нормирования из `okpd2Refs` и публикует индекс правил НПА. Пока индекс
  не загружен, `auctionListControl.ts` работает по историческому эталону 471-р
  2022 года. `needs_review` возвращается флагом и не скрывается от человека.

## Запуск и проверки

```powershell
$env:EIS_STORE='postgres'
$env:ASPNETCORE_URLS='http://localhost:5099'
$env:ASPNETCORE_ENVIRONMENT='Development'
$env:Npa__Enabled='false'
dotnet run --project src/Csms.Api --no-build --no-launch-profile
```

- Сборка: `dotnet build src/Csms.Api -v q --nologo` — 0 ошибок, 0 предупреждений.
- Тесты: `$env:EIS_TEST_DB = 'Host=localhost;Port=5433;Database=csms_eis;Username=postgres'; dotnet test tests/Csms.Tests -v q --nologo`
  — 66 пройдено (последний прогон).
- Tesseract: `C:\Program Files\Tesseract-OCR\tesseract.exe`; tessdata —
  `ocr/tessdata` (`configs/tsv` лежит в git с `tessedit_create_tsv 1`, а
  `rus.traineddata` скачивается скриптом `scripts/fetch-tessdata.ps1` и в git
  не коммитится). Флаг `--tessdata-dir` обязателен до `tsv`.
- Строка подключения: `Host=localhost;Port=5433;Database=csms_eis;Username=postgres`
  (системный кластер 5432 не трогать). Перед пересборкой остановить процесс на
  5099. PowerShell портит кириллицу в консоли — ответ писать в UTF-8-файл.
