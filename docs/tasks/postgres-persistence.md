# Задача для агента: сохраняемость пакетов в PostgreSQL

Бриф для агента, который будет делать настоящее хранилище шлюза. Прочитать до
`AGENTS.md` и `docs/eis-open-questions.md`. Вопросы по брифу — к заказчику
через комментарий в PR, а не самовольные решения.

## Зачем

Пакеты сведений и журнал переходов сейчас живут в памяти процесса
(`InMemoryEisPackageRepository`). Это значит:

- при перезапуске сервиса теряется всё, включая статус «Принят ЕИС» и журнал
  подписания;
- нет защиты от одновременных действий (два нажатия «Отправить»);
- журнал нигде не зафиксирован, то есть не доказывает, кто и что подписывал.

## Цель

EF Core + Npgsql: репозиторий поверх существующего интерфейса, миграция,
подключение через конфигурацию. **Домен (`Csms.Domain`) и API-слой не
трогать**: они уже проверены и работают.

## Что уже есть (не переделывать)

- `Csms.Application/IEisPackageRepository.cs` — интерфейс: `ListAsync`,
  `FindAsync`, `AddAsync`, `SaveAsync`.
- `Csms.Infrastructure/InMemoryEisPackageRepository.cs` — эталон поведения,
  на нём завязаны 20 тестов.
- `Csms.Domain/EisPackage.cs` — переходы статусов, проверка хеша подписи,
  журнал (`history`).

## Обязательные ограничения

1. **Статус пакета меняется только методом домена.** Публичных сеттеров нет
   намеренно. Репозиторий сохраняет уже изменённый объект, но не «ставит»
   статусы сам.
2. **Проверка хеша подписи остаётся.** Репозиторий не имеет права принять
   подпись, не сшедшуюся с содержимым: это делает домен и сервис.
3. **Заглушка не выдаётся за обмен** (правило из `AGENTS.md`). Задача только
   про хранение, не про XML и не про транспорт.
4. **Секреты не в коде и не в коммите.** Строка подключения — переменная
   окружения `ConnectionStrings__EisDb` или user-secrets. В репозиторий
   попадает только пример без пароля.
5. **Сохранять всё, что приходит в API**: `payloadSchemaVersion`,
   `isPlaceholderFormat`, `signatureBase64`, `signerThumbprint`, `eisGuid`,
   `flkErrors`, `history`. Не «оптимизировать» состав на месте: фронт читает
   эти поля по контракту, он в другом репозитории.
6. **Журнал — только на дозапись.** События `history` не редактируются и не
   удаляются. Если это дешёво закрыть на уровне БД (триггер или отсутствие
   прав UPDATE/DELETE на таблице событий) — закрыть.

## Состав работы

1. `EfCoreEisPackageRepository` + `EisDbContext` в `Csms.Infrastructure`
   (пакеты EF Core и Npgsql — с фиксированной версией, не «последняя»).
2. Миграция `AddPostgresPersistence`. Схема `eis` (если схема занята —
   зафиксировать в миграции и написать об этом в PR).
3. Оптимистичная блокировка от двойной отправки: в таблице пакетов —
   версия/`xmin`, при расхождении версий репозиторий возвращает конфликт и
   сервис отвечает 409 по-русски (см. `DomainExceptionHandler`). В домен
   версионирование **не переносить**, если его там нет.
4. `Program.cs`: регистрация EF и репозитория. Переключатель
   `EIS_STORE` (`memory` | `postgres`), **по умолчанию `memory`** — иначе
   `dotnet test` и локальный запуск упрутся в несуществующую БД, пока её нет.
   При `postgres` без строки подключения сервис должен честно падать с
   понятным сообщением, а не молча уходить в `memory`.
5. Тесты: 20 существующих обязаны проходить **без БД**. Интеграционные
   тесты — только если задана переменная `EIS_TEST_DB`, иначе пропускать.
6. `scripts/smoke.ps1`: проверку «пакет пережил перезапуск» добавлять только
   в ветку с Postgres и помечать в выводе; с `memory` сценарий не должен
   ломать общий OK.

## Окружение на 2026-11-18 (проверено)

- Postgres на машине **не найден**: служб с «postgres» в имени нет, порт 5432
  не слушает, `psql` не в PATH. Заказчик: «вроде ставил, мб снёс». Значит
  первым шагом — поднять локально (Docker Desktop или установщик), проверить
  `5432`, и только потом гнать миграцию.
- База для шлюза — `csms_eis`, схема `eis`. Свои базы шлюз не делит ни с кем.

## Приёмка

- `dotnet build` и `dotnet test` зелёные **без** поднятой БД.
- С поднятой БД: созданный через API пакет и его журнал на месте после
  перезапуска сервиса; два одновременных `POST /send` дают один переход;
  подпись с несошедшимся хешем по-прежнему отклоняется (409).
- `scripts/smoke.ps1` печатает OK в обоих режимах `memory` и `postgres`.
- Незавершённые пункты — перечислить в сообщении коммита, а не выдавать
  частичную работу за готовую.

## Чего в задачу не входит

- Настоящий XML и транспорт (ждут Альбом форматов и регистрацию ВС) —
  см. `docs/eis-open-questions.md`.
- Перенос данных из `db.json` (это фронт и json-server, другой репозиторий).
- Продовое развёртывание, бэкапы, реплики.

## Порядок работы

1. `git pull`, ветка `feat/postgres-store`, пушить **в ветку**, не в `main`.
2. Готово → PR (или комментарий с хешами коммитов) с перечнем проверок.
3. Чужие незакоммиченные правки в репозиторий не брать.
