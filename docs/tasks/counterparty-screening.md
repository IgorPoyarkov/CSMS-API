# Проверка контрагентов по публичной выгрузке ст. 19.28 КоАП

## Границы

- Источник — только публичная страница ЕИС
  `https://zakupki.gov.ru/epz/main/public/document/view.html?sectionId=2369&strictEqual=false`
  и файл XLSX по ссылке `downloadDocument.html?id=…`. Никаких токенов, PIN,
  ЭЦП и внутренних сервисов.
- Выгрузка — это сведения о привлечении **к административной ответственности
  по ст. 19.28 КоАП**, а не реестр недобросовестных поставщиков (РНП) сам по
  себе. В сообщениях и API используем точное наименование источника; blanket-
  совпадения по любым другим статьям КоАП не выдаём за эту проверку.
- Файл хранится и разбирается локально. Новые NuGet-пакеты не добавляются:
  XLSX читается как ZIP + XML через `System.IO.Compression` / `System.Xml.Linq`.
- Чужие незакоммиченные правки `EfCoreReferenceDataStore.cs` и
  `InMemoryReferenceDataStore.cs` не трогать и не включать в коммит.

## Приёмка

1. Раз в сутки (настраивается) воркер читает страницу списка, узнаёт текущий
  `id` документа и дату публикации, скачивает XLSX и считает SHA-256 байт.
2. **Парсинг выполняется только если изменился `id` или SHA-256.** Если файл
   тот же — состояние `UpToDate`, прежние данные остаются на месте.
3. Разобранные записи и манифест складываются в каталог
   `EIS_COUNTERPARTIES_ROOT` (по умолчанию `<bin>/counterparties`) с атомарной
   подменой `current`; при ошибке валидации активный снимок не заменяется.
4. Обязательные колонки B–J проверяются до записи; невалидная дата или строка
   прерывает импорт с русским сообщением в статусе.
5. API: `GET /api/eis/counterparties/status`, `POST /api/eis/counterparties/update`,
   `GET|POST /api/eis/counterparties/check` (ИНН / ОГРН / КПП). Ответ проверки
   содержит совпадения и идентификатор выгрузки, на которой она выполнена.
6. `dotnet build` и `dotnet test` зелёные.

## Чего делать не надо

- Не добавлять EF-миграцию и DbSet: снимок tiny (около 1000 строк), файлового
  хранилища с in-memory индексом достаточно и оно не зависит от PostgreSQL.
- Не менять статусы пакетов/контрактов в обход доменных методов.
- Не встраивать проверку в `EisPackageService` / `AcceptanceService` без
  отдельного решения: сейчас это извещающая проверка, а не основание отказа.
