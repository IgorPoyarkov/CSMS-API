# XSD-схемы ЕИС 44-ФЗ

Сюда кладётся Альбом форматов ЕИС — официальные XSD-файлы. Пока их нет,
шлюз работает с честно помеченным черновиком (`placeholder-v0`) и не пытается
выдать его за документ, который пройдёт ФЛК.

## Как добавить схему

1. Создай папку с версией формата, например `schemas/14.2/`.
2. Положи в неё **все** XSD этой версии (включая `BaseTypes.xsd`,
   `CommonTypes.xsd` и остальные включения) — каталог компилирует их вместе.
3. Передай генератору эту версию как `SchemaVersion` (сейчас его задаёт
   `PlaceholderXmlBuilder`; в рабочей реализации — маппер из доменной модели).
4. Перезапусти шлюз: `EisSchemaCatalog` кеширует схемы на старте первого
   обращения к версии.

Путь по умолчанию — `schemas/` рядом с исполняемой сборкой (`bin/Debug/net9.0`).
При локальном запуске удобнее переопределить его переменной:

```powershell
$env:EIS_SCHEMAS_ROOT = "D:\Свои проекты\CSMS\csms-api\schemas"
dotnet run --project src/Csms.Api
```

## Что происходит после появления схем

- `EisPackageService` проверяет собранный XML по XSD **до** подписания и
  сохранения; ошибки приходят в ответе API, а не от ФЛК после отправки.
- Если для версии схем нет, проверка пропускается — это честный переходный
  режим, а не «проверка прошла успешно».
- Версия живёт отдельно от домена: смена формата ЕИС не требует правок
  фронтенда или базы данных (Tasks 12 §5.3).

Синтетический пример загрузки и проверки — `tests/Csms.Tests/EisSchemaCatalogTests.cs`.
Он не является схемой ЕИС и нужен только чтобы проверить сам механизм.
