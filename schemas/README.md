# XSD-схемы ЕИС 44-ФЗ

В этой папке лежит Альбом форматов ЕИС — официальные XSD-файлы. С 2026-11-19
шлюз **скачивает их автоматически** с публичной страницы документов ЕИС;
ручная раскладка осталась как запасной вариант.

## Автообновление

Источник — страница
`https://zakupki.gov.ru/epz/main/public/document/view.html?sectionId=432`,
на которой публикуются архивы «Интеграционные схемы ЕИС версии X.Y».
Ссылка на архив содержит `id`, меняющийся с каждой версией, поэтому шлюз:

1. читает страницу и берёт из неё номер версии и `id` самого свежего архива;
2. скачивает ZIP (с `Referer` на страницу — без него ЕИС отдаёт 404);
3. проверяет размер, PATH-безопасность и компилирует все XSD в `XmlSchemaSet`;
4. атомарно подменяет папку `schemas/<версия>/`, не трогая предыдущую до
   успешной проверки;
5. пишет `.manifest.json` с `id`, SHA-256 и числом файлов — пока `id` не
   изменился, архив повторно не скачивается.

Первая проверка происходит сразу при старте, дальше раз в 12 часов
(`EisSchemas:Update:CheckIntervalMinutes` в `appsettings.json`).

### Настройки

Раздел `EisSchemas:Update` в `appsettings.json`; переменные окружения
`EisSchemas__Update__*` переопределяют значения:

| Ключ | По умолчанию | Смысл |
| --- | --- | --- |
| `Enabled` | `true` | включить фоновую проверку |
| `ListingUrl` | страница документов ЕИС | откуда брать номер версии и id |
| `DownloadUrlPrefix` | `…downloadDocument.html?id=` | префикс ссылки на ZIP |
| `CheckIntervalMinutes` | `720` | период проверки |
| `HttpTimeoutSeconds` | `60` | таймаут запроса |
| `MaxArchiveBytes` | `32 МБ` | предел размера архива |
| `MaxEntries` / `MaxExtractedBytes` | `500` / `64 МБ` | защита от ZIP-бомбы |
| `AutoPromote` | `true` | `false` — только подготовить в `.incoming/`, без подмены активных схем |

### Статус и ручная проверка

```powershell
curl http://localhost:5099/api/eis/schemas/status
curl -X POST http://localhost:5099/api/eis/schemas/update
```

`status` читается без обращения к ЕИС. `POST /update` запускает проверку
немедленно; при ошибке скачивания/компиляции отдаёт `502` с причиной, а
активные схемы остаются прежними. В ответе: `state` (`Checking`, `UpToDate`,
`Installed`, `Staged`, `Error`, `Disabled`), версия, `id`, SHA-256, число
файлов и время последней успешной проверки.

### Известный дефект архива ЕИС

В архиве версии 17.0 файл `getDocsLE-ws-api.xsd` содержит лишний `>` сразу
после XML-декларации, из-за чего `XmlReader` отклоняет файл. Загрузчик убирает
ровно этот символ и пишет предупреждение в лог. Править схемы молча нельзя:
любое ещё неизвестное отличие должно ломать сборку, а не проходить незаметно.

## Ручная установка

Если автообновление отключено (`Enabled=false`) или нужно зафиксировать
версию вручную:

1. Создай папку с версией формата, например `schemas/17.0/`.
2. Положи в неё **все** XSD этой версии (включая `BaseTypes.xsd`,
   `CommonTypes.xsd` и остальные включения) — каталог компилирует их вместе.
3. Передай генератору эту версию как `SchemaVersion` (сейчас его задаёт
   `PlaceholderXmlBuilder`; в рабочей реализации — маппер из доменной модели).
4. Перезапусти шлюз или вызови `POST /api/eis/schemas/update` — каталог
   кеширует схемы на первое обращение к версии, а обновлятор сбрасывает кеш
   после подмены файлов.

Путь по умолчанию — `schemas/` рядом с исполняемой сборкой (`bin/Debug/net9.0`).
При локальном запуске удобнее переопределить его переменной:

```powershell
$env:EIS_SCHEMAS_ROOT = "D:\Свои проекты\CSMS\csms-api\schemas"
dotnet run --project src/Csms.Api
```

## Что происходит после появления схем

- `EisPackageService` проверяет собранный XML по XSD **до** подписания и
  сохранения; ошибки приходят в ответе API, а не от ФЛК после отправки.
- Если для версии схем нет, проверка пропускается — это честный переходный
  режим, а не «проверка прошла успешно».
- Версия живёт отдельно от домена: смена формата ЕИС не требует правок
  фронтенда или базы данных (Tasks 12 §5.3).
- Мапперы из доменной модели в XSD-классы по-прежнему пишутся человеком:
  автообновление меняет только файлы схем, а не смысл полей.

Синтетический пример загрузки и проверки — `tests/Csms.Tests/EisSchemaCatalogTests.cs`.
Он не является схемой ЕИС и нужен только чтобы проверить сам механизм.
Тест `Настоящий_архив_ЕИС_устанавливается_и_компилируется` проверяет реальный
архив, если задать `EIS_XSD_ZIP=<путь к zip>` (без сети).
