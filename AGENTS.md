# Инструкции для AI-агентов

Репозиторий бэкенда CSMS: шлюз обмена с ЕИС. Фронтенд живёт отдельно (`CSMS`)
и работает с этим сервисом по HTTP.

## Обязательный порядок работы

1. **Перед задачей** — `git pull`, посмотреть, что пришло.
2. **После задачи** — `dotnet build` и `dotnet test` должны быть зелёными,
   затем коммит и пуш. Незакоммиченных правок не оставлять.
3. Незавершённые блоки помечать в сообщении коммита.

## Правила, которые здесь важнее стиля

- **Не выдавать заглушку за настоящий обмен.** Пока нет XSD из Альбома форматов
  ЕИС, XML остаётся `placeholder-*`, а `isPlaceholderFormat` в API — `true`.
  Придумывать «правильный на вид» формат запрещено: такой документ отклонят на
  ФЛК, а ошибка всплывёт у заказчика.
- **Статус пакета меняется только методом домена.** Публичных сеттеров нет
  намеренно: «нарисовать» статус в обход проверок нельзя.
- **Ошибки для человека — по-русски.** Сообщения домена показываются в
  интерфейсе, поэтому пишутся так, чтобы их понял заказчик, а не только
  разработчик. Технические имена статусов остаются в API и логах.
- **Комментарии в коде — на русском**, объясняют «зачем», а не «что».

## Проверки

```powershell
dotnet build
dotnet test
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/smoke.ps1   # нужен запущенный сервис
```

## Ловушки окружения

- Windows PowerShell 5.1 читает `.ps1` без BOM как ANSI: русский текст в
  скриптах превращается в мусор. Файлы `scripts/*.ps1` сохранять **с BOM**.
- Консоль по умолчанию не в UTF-8 — в скриптах выставлять
  `[Console]::OutputEncoding`.
- `Microsoft.AspNetCore.OpenApi` без версии ставит 11.x и не собирается на
  `net9.0`: версия должна быть `9.0.*`.
