# CSMS API — шлюз обмена с ЕИС

Отдельный репозиторий от фронтенда (`CSMS`): фронт работает с этим сервисом по
HTTP, контракт — OpenAPI по адресу `/openapi/v1.json`.

Смысл сервиса: превратить «сведения о СМП» в пакет, который можно подписать,
отправить в ЕИС и проследить до результата проверки. Не «сформировать файл,
который человек куда-то отнесёт», а провести документ по состояниям и показать,
что с ним происходит.

## Что уже работает

- **Жизненный цикл пакета**: `Draft → Signing → Signed → SentToEis → FlkChecking → AcceptedInLk` и ветки `RejectedByFlk`, `SendFailed`. Переходы защищены в домене: отправить неподписанное или принять без ответа ЕИС нельзя.
- **Подпись разделена на две части.** Сервер отдаёт содержимое и его SHA-256; подписывает браузер на рабочем месте заказчика (ключ остаётся в токене); сервер получает подпись и **сверяет хеш** — подпись под другим документом не пройдёт.
- **Ошибки ФЛК как данные**: код, поле, текст, подсказка. Они возвращаются в пакете, а не пишутся в лог.
- **Журнал переходов**: кто, когда, из какого статуса в какой.
- **Автообновление XSD ЕИС**: страница → ZIP → проверка `XmlSchemaSet` → атомарная подмена. Каталог документации отдаётся через `/api/eis/schemas/catalog`, изменения — через `/changes` и SSE `/events`.
- **Контур доступа**: пользователи, организации, сотрудники, контрактная служба, роли и права в PostgreSQL (схема `access`), вход по email/паролю с PBKDF2 и сессионным Bearer-токеном. Сервер сам вычисляет эффективные права по составу КС (приказ № 158н); фронт получает готовый профиль через `/api/access/*`.
- **52 теста** на правила домена, доступ, сквозной сценарий и обновление схем (2 postgres-теста пропускаются без `EIS_TEST_DB`).

## Что пока заглушка — и это видно в API

| Заглушка | Чем станет | Как это заметно сейчас |
|---|---|---|
| `PlaceholderXmlBuilder` | Генерация по XSD из Альбома форматов ЕИС | `payloadSchemaVersion = "placeholder-v0"`, `isPlaceholderFormat = true` |
| `MockEisTransport` | SOAP поверх ГОСТ-mTLS к `int44.zakupki.gov.ru` | Ответы детерминированы и зависят только от номера контракта |
| `InMemoryEisPackageRepository` | База данных | Пакеты исчезают после перезапуска |

Черновой XML нельзя считать файлом обмена: он не пройдёт ФЛК. Флаг в API
существует именно для того, чтобы это нельзя было перепутать.

## Запуск

```powershell
dotnet run --project src/Csms.Api
```

Сервис слушает `http://localhost:5099` (см. `Properties/launchSettings.json`).
Для браузера разрешены origin-ы `http://localhost:5173` (Vite dev) и
`http://localhost:4173` (preview) — точечно, а не «любой»: иначе первый же
открытый чужой сайт смог бы дёргать API от имени заказчика.

Фронтенд (`csms`) ходит сюда через `VITE_EIS_API_URL` (по умолчанию тот же
`http://localhost:5099`). Экран — «Пакеты ЕИС» (`/eis/packages`).

Контур доступа использует тот же адрес; переменная `VITE_ACCESS_API_URL` имеет
приоритет. Импорт сидов из фронтового `db.json` (пароли хешируются в API):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/import-access.ps1 -AdministratorEmail "test1@test.test"
```

Затем вход: `POST /api/access/login` (`{"email":"...","password":"..."}`) →
`token` + профиль; токен передаётся как `Authorization: Bearer …` в
`GET /api/access/me`. Без токена — 401, при неверном пароле — 409.

Сквозная проверка (сервис должен быть запущен):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/smoke.ps1
```

Скрипт создаёт пакеты, подписывает, отправляет, опрашивает ФЛК и проверяет
отказы: отправку без подписи, подпись под другим содержимым, отказ ФЛК,
недоступность шлюза. Все проверки должны завершиться строкой `OK`.

### XSD Альбома ЕИС и документация по типам

Установленные XSD версии 17.0 лежат в `schemas/17.0/` и закоммичены: это снимок,
который скачивает и проверяет `EisSchemaDownloader`. Сервис обновляет его сам
(статус — `GET /api/eis/schemas/status`, ручная проверка — `POST /update`).

Генератор документации пересобирает из XSD каталог и TypeScript-типы для
фронтенда:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/generate-schema-docs.ps1
```

Результат — `csms/public/eis-schemas/catalog.json` и
`csms/src/services/Eis/generated/eisSchemas.generated.d.ts`. Во фронте по ним
работает обозреватель `/eis/schemas` («Swagger для XSD»): версии, пространства
имён, типы, поля и описания. Подробнее — `schemas/README.md`.

### Локальная база (пока хранилище в памяти — не обязательна)

Проектный кластер PostgreSQL 17 для шлюза: порт **5433**, база `csms_eis`,
аутентификация `trust` на localhost. Системную установку на 5432 не трогаем —
там чужой кластер с неизвестным паролем.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/pg-local.ps1
```

Строка подключения — в user-secrets проекта `Csms.Api`
(`ConnectionStrings:EisDb`), в репозиторий не попадает.

## Структура

```
src/
  Csms.Domain/          пакет, статусы, правила переходов, ошибки ФЛК
  Csms.Application/     сценарии: создание, подпись, отправка, опрос результата
  Csms.Infrastructure/  заглушки: хранилище в памяти, XML, транспорт
  Csms.Api/             HTTP, контракт OpenAPI, обработка ошибок
tests/
  Csms.Tests/           правила домена и сквозные сценарии
scripts/
  smoke.ps1             проверка живого сервиса
  pg-local.ps1          проектный кластер PostgreSQL (порт 5433)
  generate-schema-docs.ps1 каталог XSD и TS-типы для фронтенда
tools/
  EisDocGenerator/      чтение XSD через XmlSchemaSet, вывод JSON и .d.ts
schemas/
  17.0/                 снимок официальных XSD Альбома ЕИС
docs/
  eis-open-questions.md что нужно от ЕИС, чтобы выйти из заглушек
  tasks/                брифы для агентов (Postgres-хранилище и др.)
```

Зависимости направлены внутрь: `Api → Infrastructure → Application → Domain`.
Домен не знает ни про HTTP, ни про базу, ни про SOAP — поэтому его правила
проверяются тестами без сети и без сертификатов.

## Чего не хватает для настоящего обмена

Кратко: **XSD именно для наших документов** (исполнение контракта, привлечение
СМП — альбом ТФФ по 658/215н и 918; общие интеграционные схемы ЕИС уже
скачиваются автоматически) и **регистрация внешней системы (ВС)** с доступом по
IP в личном кабинете ЕИС. Подробно —
[docs/eis-open-questions.md](docs/eis-open-questions.md).
